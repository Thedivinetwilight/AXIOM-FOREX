# AX-SCALPER Windows maintenance-window checklist

**Do not apply this update or install dependencies into a running workstation. The operator must stop the active workstation first.** This checklist is a future maintenance procedure, not a claim that Windows or MetaTrader 5 has been verified.

1. **Prepare and preserve:** schedule a maintenance window; stop the workstation normally; confirm its processes have exited. Back up the project and separately preserve all `scalper_paper.local.json`, capital/settings, evidence artifacts, imports, JSONL ledgers and `.head.json` sidecars. Do not delete, truncate, replace, or “repair” a ledger to clear a blocker. Keep backups outside Git and protect them as user data.
2. **Update safely:** fetch and inspect the intended feature-branch update; confirm it is a fast-forward from the operator's expected tip. Do not change `main`. Review the diff before updating the application files. If the tree contains unrelated changes, stop and investigate rather than resetting or cleaning it.
3. **Virtual environment/dependencies:** use the project's documented Windows virtual-environment procedure and install only pinned/project-declared dependencies into that environment while the workstation is stopped. Check Python version compatibility and install/verify `tzdata` when the selected Windows/Python environment needs an IANA timezone database. Do not install into the active process or global interpreter. Record package versions and installation output.
4. **Read-only connection and account:** start the workstation only after update/dependency checks. Explicitly press Connect; no background connection is permitted. Verify the displayed account identity and account mode. Confirm that the selected symbol is the exact broker symbol, not a guessed pair alias.
5. **Broker symbol/specification review:** read the connected terminal's symbol catalogue and compare point size, digits, contract size, volume min/step/max, stop level, currencies and conversion terms with local settings. Stop if any term is absent, stale, inconsistent or unexpectedly changed. Do not infer or substitute a contract fact.
6. **Costs, capital and risk:** confirm the locally declared PAPER capital and currency, observed commission/slippage/swap treatment, and every configured risk bound. Do not infer broker costs or account capital. If exact values cannot be verified, leave trading blocked.
7. **PAPER recovery:** inspect the recovery status and referenced ledger/head sidecar read-only. If exact restoration is unavailable or any integrity/config/strategy/symbol check fails, keep the book blocked and preserve the files. Do not start a replacement book, auto-flatten, or attach stored positions to another strategy. The current build does not implement exact restart restoration.
8. **Observation and PAPER controls:** if appropriate, use the explicitly labelled observation-only action; verify it has zero attached strategies, zero entries and zero fills. A trading PAPER start must remain blocked without a genuinely admitted candidate, healthy fresh quotes, valid configuration and clear recovery. If a candidate is admitted, verify displayed data source, quote age, local-only fills and ledger integrity. Stop normally and confirm open local positions remain recorded and were not flattened.
9. **LIVE review (separate authorization):** no AX-SCALPER LIVE handoff is implemented. Do not treat PAPER outcomes or signatures as LIVE authorization. For any unrelated existing LIVE strategy, use only `/live` and independently review account identity, mode, strategy evidence, plan, arming confirmation, preflight, risk, idempotency/unknown-outcome state, reconciliation and protective orders. LIVE is off by default and requires the existing explicit operator actions.
10. **Acceptance record:** run the documented tests in the Windows environment, then a read-only smoke check of the exact terminal/version during the approved window. Record Windows version, Python/MT5 package/terminal versions, account mode, symbol/spec facts, costs/risk confirmation and results. Any failing check means stop and keep entries disabled.

Repository fixture tests are not Windows tests, real-MT5 tests, broker-data evidence or proof of profitability. Never apply package or code updates while the reported currently-running system is active.
